# 0009: UI text lives in Paraglide

Status: accepted, 2026-11

## Decision

- All web UI text is Paraglide messages (`ui/packages/frontend/messages/en.json`, base locale `en`). Parameter labels and help texts are keys `param_<name>_label` / `param_<name>_help`; enum option labels are `optionTexts` in `parameter-text.ts`.
- The firmware keeps no UI-only metadata: no labels, help texts, sections or order. `ParamDef` holds key, type, limits, default and reboot flag; `/api/parameters` sends those plus `requiresReboot`.
- Enum option labels stay in firmware as the wire vocabulary: MQTT commands and provisioning send label text (`Choice::OPTIONS`, `set_from_str`). The UI shows its own label per value and falls back to the firmware label.
- OLED text stays in firmware (ADR 0007).
- The UI language switch is on About. It lists the locales Paraglide compiled (only `en`) and reloads the page (`setLocale`). It is separate from the device's `display.language` (OLED).

## Consequences

- Module-scope `m.*()` calls freeze the locale at import. Labels are passed as functions and called at render.
- Paraglide's message-format and function-matcher plugins are devDependencies, referenced by local path in `project.inlang/settings.json`. Compile needs no network; the plugins never ship in the UI bundle.
- No CI check for new hard-coded text: review catches it. Add one if regressions show up.
- Adding a language: a new `messages/<locale>.json`, a name in `localeNames` (`lib/language.ts`), and the enum/option texts it needs.
