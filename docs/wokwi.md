# Wokwi Emulator (VS Code)

## Setup

1. Install the Wokwi VS Code extension.
2. Copy the example config into the LittleFS data directory:

```
cp docs/example_config.json data/config.json
```

3. Build firmware + filesystem and generate the Wokwi image:

```
pio run -e esp32_usb -t wokwi
```

4. In VS Code, run **Wokwi: Start Simulator**.

Wokwi loads the configuration from `wokwi.toml` and `diagram.json` in the repo root,
and uses `.pio/build/esp32_usb/firmware_merged.bin` (generated by the script above),
which bundles the bootloader, boot_app0, partitions, firmware, and LittleFS image.

When using Wokwi WiFi, the CleverCoffee web UI is available at
`http://localhost:8180` (see the port forward in `wokwi.toml`).

## WiFi config (skip portal)

On first boot, if no WiFi credentials are stored in NVS, the firmware automatically
reads `/config.json` from LittleFS and seeds NVS with its values (one-time only).
This means you can pre-configure WiFi (and any other setting) without touching the
web UI — just provide a `data/config.json` before flashing.

`data/config.json` is covered by the `data/*` entry in `.gitignore` — do not commit
it (it may contain credentials).

Set `system.wifi.ssid` / `system.wifi.password` to connect directly and skip the
WiFiManager portal. For Wokwi, use the built-in `Wokwi-GUEST` open network:

```json
{
  "system": {
    "wifi": {
      "ssid": "Wokwi-GUEST",
      "password": ""
    }
  }
}
```

`docs/example_config.json` is a ready-to-use full config with all sensor settings
matching `diagram.json` and WiFi pre-set to `Wokwi-GUEST`.

## Expected first-boot log messages

These messages are normal on a fresh flash and do not indicate a problem:

```
[E][Preferences.cpp:50] begin(): nvs_open failed: NOT_FOUND
```

The NVS partition is empty on first boot. The firmware seedes NVS from
`/config.json` (if present) and initialises NVS on the first write.
The error disappears on subsequent boots once NVS has been written.
