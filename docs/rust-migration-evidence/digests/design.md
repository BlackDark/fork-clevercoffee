## 1. Target architecture (as this branch proposes it)

- Platform fixed by ADR 0004: **ESP-IDF / std**, `esp-idf-sys` 0.38.1 + `esp-idf-hal` 0.47 + `esp-idf-svc` 0.53, target `xtensa-esp32-espidf`, **ESP-IDF v5.3.6** pinned via `ESP_IDF_VERSION` (`docs/adr/0004-rust-migration-platform-selection.md`).
- **Two Cargo workspaces**: root workspace holds `crates/cc-domain`, `crates/cc-hal`, `crates/cc-drivers` (all `no_std`) and `exclude`s `firmware/`; `firmware/` workspace holds `esp32` (binary), `cc-board`, `cc-app` (`std`). `firmware/` depends on `../crates/*` by path as dependencies, not members (`docs/rust-migration/tooling.md` §3, `docs/rust-migration/architecture.md` §6).
- **Five tasks + one ISR** (`architecture.md` §2.2): `control` (core 0, prio 18, fixed 10 ms tick, 8 KB), heater **ISR** on GPTimer, `ui` (core 1, prio 6, 100 ms, 6 KB), `net` (core 1, prio 8, 8 KB), `http` (IDF `httpd`, 8 KB), `storage` (core 0, prio 5, 4 KB). `main` is bring-up only: safe outputs → start tasks → park.
- **Concurrency model is threads, not async**: `esp_idf_hal::task::ThreadSpawnConfiguration` for name/prio/core/stack. `embassy-executor` is rated an outright disqualifier because `esp-idf-hal`'s `critical-section` impl is a FreeRTOS recursive mutex, not ISR-safe (`docs/rust-migration/compatibility-matrix.md` §2.4).
- **Three cross-task primitives only** (`architecture.md` §2.3): bounded `Command` queue (depth 16, `T: Copy` enforced — `heapless::String<N>`/index, never `String`/`Vec`/`Box`), `StateSnapshot` seqlock (one writer, many readers), and `HeaterDuty: AtomicU16` (0..=1000 ms-on per 1000 ms window).
- **Safety effects never traverse a queue**: interlock evaluation and the actuator write happen in the same tick by direct call (`architecture.md` §2.4, and repeated as a carried rule in `SKILL.md` §6b).
- **Heater is made structural**: `HeaterCommand::duty(requested, &Interlocks)` is the only constructor and is fallible; the ISR reads only `HEATER_DUTY` (`architecture.md` §3). This is the C1 fix.
- **Boot layout guard** `layout_ok(&[PartitionInfo]) -> Result<(), LayoutFault>` requiring a `ccfs`+`littlefs` partition; runs after actuators are safed, before anything else, and **halts** on failure (`architecture.md` §3.1, ADR 0005 §2, task `BOOT-1`).
- **State machine lives in `cc-domain::state`**: 18 `#[repr(u8)]` state ids with explicit discriminants, transition table, and `BaseState`'s pre-emptive chain in exact order emergency > sensor error > tank empty > PID disabled > state-specific, with per-state exclusions; range predicates (`isBrewState` 31..34, `isBackflushState` 60..63, LED eligibility ≤63) are replaced by **explicit sets** asserted against the ranges (`architecture.md` §6.1, task `DOMAIN-1`).
- **HAL seam is `cc-hal`**, trait-only: `DigitalOut`, `DigitalIn`, `Clock`, `HeaterPwm`, `TempSource`, `KvStore`, `SymbolCapture` — no trait mentions `esp_idf`; `Clock` exists to kill the C++'s two-clocks problem (`architecture.md` §6.2).
- **`cc-drivers`**: `ds18b20` via `onewire` 0.4.0, hand-written `abp2` (~150 LOC), `ssd1306`/`oled_async` behind one `DrawTarget`, TSIC RMT glue; generic over `embedded-hal` 1.0 so each is host-testable on a mock bus.
- **`cc-board`** is the only crate that knows ESP-IDF: pin map as constants, `cc-hal` impls, `KvStore` over `EspNvs`, GPTimer heater PWM. Board variants are a **feature, not a directory tree**.
- **Config persistence**: NVS namespace `wifi` = plain `ssid`/`pass` strings; namespace `cfg` = `ver` (u16) + one `postcard`-encoded blob for the whole configuration; saving is one atomic write from the `storage` task instead of ~97 open/write/close cycles (ADR 0005 §3, `architecture.md` §6.4, task `APP-2`).
- **`config.json` is the only compatibility surface** (C12): nested dotted-path import/export in `cc-domain::config::json`, accepting bare values *or* `{value: …}` wrappers, rejecting legacy flat dotted-key documents, returning a **report** (accepted / rejected-with-reason / unknown-key / out-of-range) instead of a bool.
- **HTTP/MQTT/OTA live in `cc-app`**, holding *no* control logic — deliberately so it can be the crate that is never host-tested.
- **Wi-Fi provisioning v1 is over USB**: a host script builds a real NVS image with Espressif's own `esp-idf-nvs-partition-gen` and writes it at `0x9000` with `espflash write-bin`, with credentials deliberately outside the config blob (`tooling.md` §6).

## 2. Key decisions and their rationale

| Decision | Chosen | Why | Rejected alternatives |
|---|---|---|---|
| Rust platform | ESP-IDF / std (`esp-idf-svc`), target `xtensa-esp32-espidf` | Threads model maps onto the existing single-loop+ISR firmware; every needed peripheral/service already has a wrapper; Wi-Fi is the stack the device is proven on (`adr/0004`) | bare metal `esp-hal`+`esp-rtos`+`esp-radio` on `xtensa-esp32-none-elf` — pre-1.0 radio with appliance-hostile issues (#5889 reconnect stays broken after auth failure, #1600 no WPA3 station), and measured ~320 KiB DRAM fully allocated by official Wi-Fi examples before any app code (`compatibility-matrix.md` §3.2–3.3) |
| Binary size question | Closed by measurement, not argument: SPIKE-1 linked every needed subsystem into **997,648 B = 58.5 %** of the 1.625 MiB app partition vs the C++ at 90.4 % | The C++ had only 160 KiB headroom; `std` + `build-std` was the gating risk and is now a measured non-risk (`adr/0004` SPIKE-1) | quoting published figures (none exist for this workload); accepting the risk conditionally |
| Toolchain management | `rustup` + `espup` for Rust; **mise must not manage `rust`** | mise's `cargo` shim shadows rustup's, silently ignores `rust-toolchain.toml`, and fails as `can't find crate for core` / `'esp32' is not a recognized processor` — hit and diagnosed during SPIKE-1 (`tooling.md` §2.2, `adr/0004` Consequences) | mise-managed Rust; distro Rust |
| ESP-IDF version | **v5.3.6** | The version the crates are tested against in CI; keeps the migration an IDF 4.4 → 5.3.6 major jump rather than further (`adr/0004`) | v5.5.5 (the version the parallel branch actually ran on hardware — recorded as a divergence, `prior-implementation-findings.md` §1.3) |
| std vs no_std in crates | `cc-domain`/`cc-hal`/`cc-drivers` are `no_std` (+`alloc` in domain); only `cc-board`/`cc-app`/`esp32` are `std` | Makes all control logic host-testable with no toolchain gymnastics — the mechanism that keeps C10 true (`architecture.md` §6.1, §6.6) | one flat `std` workspace (loses the fast host test loop) |
| Concurrency | **Five FreeRTOS tasks + one ISR**, threads not async | The safety path must not share a deadline with anything blocking; `embassy-executor` is disqualified by the non-ISR-safe critical-section impl (`architecture.md` §2, `compatibility-matrix.md` §2.4) | async/embassy; staying with one free-running loop |
| Task count | 5, each with a stated timing reason | `storage` exists so a config write never happens on an HTTP handler (the C++ does exactly that) (`architecture.md` §2.2) | the parallel branch's 3 tasks, justified by measurement (`prior-implementation-findings.md` §7.4) — noted as "reasoning, not measurement" |
| Heater PWM mechanism | 10 ms **GPTimer ISR**, explicitly *not* LEDC | Now empirically justified: `ledc_ll.h:483-489` spin-waits **only on ESP32** inside a critical section, masking interrupts for a full carrier period → 300 ms interrupt-WDT panic, even at duty 0 (`prior-implementation-findings.md` §1.2) | LEDC ("costs zero CPU") — recorded as an argument that must not be revisited for this chip |
| Duty representation | `AtomicU16` milliseconds-on per 1000 ms window, **integer compare** in the ISR | A single FP instruction in a level-1 ISR panics the original ESP32 (`Coprocessor exception`, `EXCCAUSE 0x4`) because Xtensa never saves coprocessor state across an interrupt; the C++ escapes only because GCC soft-floats the same source (`prior-implementation-findings.md` §1.1) | `double` duty (as in C++), float compare |
| Heater interlock structure | Interlocks become a **constructor argument**, not a race | Makes the unsafe order unrepresentable rather than merely fixed (`architecture.md` §3) | keep "everyone races to zero the output" |
| Watchdog | Task WDT, single subscriber = `control`, driver **moved into** the control task | `TWDTDriver` is `Send` but not `Sync` and `WatchdogSubscription::feed(&mut self)` is `&mut`-bound, so control+ui subscription **cannot be built**; single-subscriber also makes "only control can feed it" structural (`architecture.md` §2.6, `prior-implementation-findings.md` §8.1) | subscribing `control` and `ui` (the earlier revision) |
| Config storage format | Single `postcard` blob + separate `ver` in namespace `cfg`; Wi-Fi keys plain and outside the blob | Removes the 15-char-key hash workaround, makes save one atomic write, and decouples provisioning and factory reset (`adr/0005` §3) | Arduino `Preferences`/`"p"+FNV-1a(dotted path)` continuation — the single hardest constraint in the migration, deleted by ADR 0005 |
| Backward compatibility | **None.** NVS restructured, new partition table, old→new OTA must not work; manual USB flash + `config.json` import/export | It removes the hardest constraint, but "not possible" has to be *enforced*, which created the new safety obligation `BOOT-1` (`adr/0005`) | keeping NVS/partition continuity (superseded argument 1 of ADR 0004) |
| Partition table | `partitions_rust_4m.csv`, `ccfs`+`littlefs`, **app slot geometry unchanged on purpose** | Renaming `spiffs`→`ccfs` is what makes an app-only old→new OTA land on a device that refuses to run; keeping 1664 KB slots means SPIKE-1's 58.5 % figure needs no re-verification (`adr/0005` §1) | 1792 KB slots + 384 KB `littlefs` as on the attached board (device-verified there, `prior-implementation-findings.md` §10) |
| Safety on wrong layout | **Halt**, not degrade | A half-migrated device still has a heater, pump and valve wired up (`architecture.md` §3.1) | fall back to defaults and run "mostly fine" |
| OTA story | Dual slots kept; **new→new OTA supported**, old→new prohibited and enforced by the layout guard | Prohibiting only old→new keeps a wanted feature (`task-list.md` `NET-4`, `adr/0005` §1) | freezing OTA entirely |
| Emergency debounce | Change from iteration-counting to **time-based** N×10 ms | Iteration counting makes the time constant vary with system load (`architecture.md` §2.5, declared in `task-list.md` `DOMAIN-5`/`PARITY-2`) | preserving iteration semantics |
| TSIC conversion formula | **Keep** the vendored library's `((raw*250)>>8-499)/10.0`, not the datasheet's | Preserves existing users' calibration offsets — a decision to keep a deviation, recorded so it is not "corrected" later (`adr/0004` deliberate changes) | datasheet formula (up to ~0.1 °C different) |
| Missing timeouts (manual brew, steam, manual flush) | **Reproduce current behaviour**, flag it | Adding them is a genuine safety fix but a user-facing behaviour change requiring approval (`architecture.md` §8 item 3) | silently adding them |
| Scope reduction | Scale (HX711 and Acaia BLE) is dead code in the C++ — never instantiated — so it is **deferred**, not ported | `getWeight()` returns 0.0; brew-by-weight cannot work as shipped (`inventory.md` §4.4, `task-list.md` Deferred) | porting the whole scale stack |
| Verification baseline | The **C++ firmware stays in the tree and buildable for the whole migration** and is the oracle; parity tests capture its behaviour rather than restating docs | `architecture.md` §7, CI job `cpp-baseline` | trusting the prose |

## 3. Pitfalls, gotchas and hard problems discovered

**Safety-critical**

1. 🔴 **The ISR reads only `pidOutput`, and `computePID()` runs *before* `updatePIDState()` zeroes it** — a window of a few ms in which the heater can be driven from a live duty cycle during `EMERGENCY_STOP`, `SENSOR_ERROR` or `STANDBY`. Combined with a non-atomic 8-byte `double` read, this is the single worst C++ defect. (inventory.md §5.7, §3.5)
2. 🔴 **A floating-point instruction anywhere in a level-1 ISR panics this chip** — `EXCCAUSE 0x4`, Xtensa never saves coprocessor state across an interrupt, `CONFIG_FREERTOS_FPU_IN_ISR` defaults off. The C++ is safe *only by accident* (GCC soft-floats the same source the `esp` target compiles to hardware FP). Verify by reading disassembly; a naive `.s` grep false-positives on `divn.s`/`un.s`/`moveqz.s`. (prior-implementation-findings.md §1.1)
3. 🔴 **BOARD-2's `LOW_TRIGGER` fail-safe default is contested and must not be implemented as written** — both the recovered oracle and the parallel branch *refuse* a `LOW_TRIGGER` heater outright, because an undriven GPIO during reset energises the heater and no firmware can prevent it. Which polarity this machine is actually wired for is unverified. Escalated, not resolved. (architecture.md §4.1 step 1, task-list.md `BOARD-2`, prior-implementation-findings.md §7.1, U14)
4. 🔴 **LEDC cannot produce a 1 Hz carrier on the original ESP32** — `ledc_ll.h:483-489` spin-waits inside `portENTER_CRITICAL`, masking interrupts for a full carrier period against a 300 ms interrupt WDT; it panics even at duty 0 because the wait precedes the duty value. (prior-implementation-findings.md §1.2)
5. 🔴 **The heater switches ~2×/s, not 100×/s** — the ISR fires at 100 Hz but the relay level changes about twice per second; anyone reading the ISR rate as the switching rate would spec a 2 kW contactor at 200 changes/s, 100× the C++ mechanical duty. Contactor's min on/off time, realised pin frequency and duty are unmeasured by either effort. (prior-implementation-findings.md §8.6, U18)
6. 🔴 **A half-migrated device boots and runs.** ESP-IDF images are relocatable across OTA slots and the old firmware's OTA accepts any `.bin`, so a C++→Rust app-only OTA yields a running machine with no `ccfs`, no assets, no config — and a heater attached. Hence `BOOT-1`. (adr/0005 "Why 'OTA is not possible' needs enforcing")
7. 🔴 **Both pump safety timeouts are dead code** — `PumpTimer::start()` is never called anywhere, so `isExpired()` is unconditionally false: the 5-minute brew limit and 60-second hot-water limit can never fire. `MANUAL_FLUSH_RUNNING` and the backflush fill/flush phases are not covered even if armed. (prior-implementation-findings.md §2 #11, inventory.md §5.11 as the weaker version)
8. 🔴 **The steam valve has no safety whitelist at all** — `openSteamValve()` checks only `emergencyMode_`, and steam and water share one physical relay (GPIO17), so an ungated steam open is an ungated water valve. (prior-implementation-findings.md §2 #2; `ValveState.h:8-11`)
9. 🔴 **Steam mode can be flipped over HTTP from any state and moves the boiler setpoint** — `WebServerManager.cpp:444-445` calls `setSteamModeActive(!isSteamModeActive())` directly, `ProcessController.cpp:119` feeds it into `updateSetpoint`; unauthenticated behind wildcard CORS with auth off by default. (prior-implementation-findings.md §11.1)
10. 🔴 **`TempSensor::isValidTemperature` is dead**, so the DS18B20 path has no range check and a fault sentinel can reach the PID and emergency-stop logic; the sentinel check itself looks for three faults only a MAX31850 produces and omits the −127 a DS18B20 actually produces. (prior-implementation-findings.md §2 #17, #18)
11. 🔴 **`PID_v1`'s output clamp lets `NaN` through** — `if (output > outMax) … else if (output < outMin) …` fails both for NaN, so the `SampleTime/1000` divide's NaN reaches `*myOutput` unclamped. The clamp is therefore itself a parity decision (`f64::clamp` panics on NaN; `min`/`max` differ again). (prior-implementation-findings.md §11.2)
12. 🔴 **`emergencyStopTemp` / `emergencyStopHysteresis` are declared but absent from the config registry** — never persisted, exported, or factory-reset, and confirmed absent from a real `config.json` export (96 leaf parameters). Safety parameters, silently lost on migration. (inventory.md §6.6, §7.1 item 10, task `DOMAIN-4`)
13. 🔴 **`clearEmergencyMode()` asymmetry** — `EmergencyStopState::onExit` does not call it; only `ProcessController` does, so emergency mode can stay latched after leaving `EMERGENCY_STOP`, silently turning every later `enableHeater`/`enablePump`/`openWaterValve` into a no-op. (inventory.md §5.8)
14. 🟠 **`disableAllHardware()` skips relays whose tracked flag says "off"**, and the heater's flag is documented unreliable while the ISR runs; the fix adopted is to write all four safe unconditionally. (architecture.md §4.2, inventory.md §5.10)
15. 🟠 **Backflush states never re-assert hardware in `update()`** — `Filling` opens pump+valve in `onEntry` and nothing re-asserts; `Flushing` fails inverted. Exactly the ADR 0003 class. (prior-implementation-findings.md §2 #13)
16. 🟠 **Missing manual-brew, steam and manual-flush timeouts**, plus two dead `*_STOPPED_DISPLAY_TIMEOUT_MS` constants. Deliberately reproduced, not fixed. (inventory.md §5.11, architecture.md §8)
17. 🟠 **The water valve is not gated on an empty tank** (only `enablePump()` is), and a scale fault takes the whole machine to `SENSOR_ERROR` with the heater off — on a scale that is never instantiated. (prior-implementation-findings.md §2 #3, inventory.md §5.12)
18. 🟠 **Emergency stop keeps heating through its ~800 ms debounce window**, and `clearEmergencyMode` requires a valid reading *and* `temp <= 100 °C` while the dead 120 °C constant is misleading. Exactly `0.0 °C` counts as valid. (prior-implementation-findings.md §2 #4, inventory.md §5.8)

**Hardware / timing / driver subtleties**

19. 🔴 **`TWDTDriver` is `Send` but not `Sync`** and `feed(&mut self)` is `&mut`-bound, so the watchdog **cannot** be shared between `control` and `ui` — this plan's own §2.6 could not be built and was revised. `TWDTConfig`'s `subscribed_idle_tasks` defaults from `CONFIG_ESP_TASK_WDT_CHECK_IDLE_TASK_CPU0/1`, and IDF subscribes idle tasks *unless* those are `n`, so "only control is subscribed" must be configured, not assumed. (prior-implementation-findings.md §8.1, architecture.md §2.6)
20. 🔴 **`esp-wifi-provisioning` would silently remove `hal::onewire` and `hal::timer` graph-wide** — it depends on `esp-idf-hal` with a non-optional `rmt-legacy`, and `not(feature="rmt-legacy")` is exactly what gates those modules; that would break BOARD-3 (heater PWM), DRV-1 and DRV-3 at once. Check with `cargo tree -e features -p esp-idf-hal | grep rmt` **before** adopting. (prior-implementation-findings.md §7.2, task `SPIKE-7` step 0, SKILL.md §6b)
21. 🔴 **A DS18B20 is fitted, not a TSIC-306** — ROM `0x41af...7928`, family `0x28`, answering 1-Wire, while `Config.h:1087` defaults to `TSIC_306` and nothing detects the mismatch. SPIKE-4 ("ZACwire decode via RMT against real TSIC hardware") **cannot run as written** and is re-scoped. (prior-implementation-findings.md §9.1, task-list.md SPIKE-4)
22. 🟠 **The TSIC no-signal timeout is 100 ms against a 10 Hz sensor** — one transmission period, zero margin, on a safety input, and the field is `uint8_t` so nothing above 255 ms is expressible. (prior-implementation-findings.md §11.3)
23. 🔴 **The TSIC change-rate filter's time base is a frame counter, not time** — it divides by a `volatile uint8_t heartbeat` incremented per ISR frame and reset only on an accepted read, so every rejected frame makes the next frame easier to accept; `heartbeat` wraps at 256. A port that divides by elapsed time is a *different filter*. Also `RUNTIME_CHANGERATE` is used in raw-count units in one file and degrees in another. (prior-implementation-findings.md §11.3)
24. 🟠 **U8g2's unsigned coordinate wrap means a glyph box above the display is clipped, not dropped** — `u8g2_is_intersection_decision_tree` has `if (v0 > v1) return 1` in both branches. A Rust port using signed coordinates with "reject if off-screen" renders **blank** where C++ renders a partial glyph. (prior-implementation-findings.md §12.2 B2, matrix U16)
25. 🟠 **`U8G2_BALANCED_STR_WIDTH_CALCULATION` is defined unconditionally**, so `getStrWidth` adds the first glyph's x-offset back in; every string starting with an inset glyph measures 1–2 px narrow and **every centred/right-aligned label moves**. (prior-implementation-findings.md §12.2 B1)
26. 🟠 **The degree sign is one Latin-1 byte and Rust `&str` cannot hold a lone `0xB0`** — `"\u{b0}"` is two bytes and the byte walk measures 30 px instead of 25 in `profont10`. Every temperature readout is affected and nothing in the compiler flags it. (prior-implementation-findings.md §12.2 B6)
27. 🟠 **Fonts cost 135 KB more as `embedded-graphics` `ImageRaw` (177,723 B) than as raw U8g2 RLE (42,722 B)** — decisive on a size-constrained target, and one of three reasons the parallel branch declined `DrawTarget`. (prior-implementation-findings.md §12.2 B10)
28. 🟠 **The blocking 10 ms ABP2 read is 20 % of the control loop, permanently** — `delay(ABP2_READ_DELAY_MS)=10` against `PRESSURE_UPDATE_INTERVAL_MS=50`. This is the headline performance number and the basis of the plan's only quantified improvement claim. A naive split-phase port silently turns the 50 ms period into 60 ms. (prior-implementation-findings.md §9.3, architecture.md §5)
29. 🟠 **`Queue<T>` is bounded by `T: Copy`** and `heapless::Deque` has no interior mutability so it cannot be a cross-task channel at all; the architecture's `Command` queue was originally described without noting either bound. (prior-implementation-findings.md §8.2, architecture.md §2.3)
30. 🟠 **A short I²C read converts the *previous* sample as fresh** — `Wire.requestFrom`'s return is discarded and the ABP2 buffers are file-scope globals. Distinct from the loud 0xFF-filled NAK case. (prior-implementation-findings.md §11.4)
31. 🟡 **Pressure percentage and bar use different divisors, so full scale reads exactly 90 %**; and percentage/bar paths give negative readings below `outputmin`. Preserved in the port (log-only field). (prior-implementation-findings.md §11.4)
32. 🟡 **`rawToCelsius` folds every raw ≤ −7040 to −127**, so all six Dallas faults report as "not connected" and the second sentinel check is unreachable; and `DEVICE_DISCONNECTED_RAW = −7040` is exactly −55 °C in 1/128 units, a range check rather than a sentinel check. (prior-implementation-findings.md §11.3)
33. 🟡 **`update_moving_average` reads uninitialised timing and divides 0/0 on its first sample** (`std::accumulate` seeded with an `int`, no zero guard). (inventory.md §4.1, prior-implementation-findings.md §2 #19)
34. 🟡 **Anti-windup's dead band exists only in `P_ON_E`** — in `P_ON_M`, the mode the brew-detection tuning set uses, there is no conditional integration at all and the integrator accumulates while saturated. A port with one unconditional gate is wrong in one mode or the other. (prior-implementation-findings.md §11.2)
35. 🟡 **Window size, PID sample time and output limits are one number in three roles**, set from `processWindowSize()`; changing the chop window changes the derivative divisor and the duty scale at once. (prior-implementation-findings.md §11.2)

**Contract / schema landmines**

36. 🔴 **`config.json` is now the only compatibility surface and its round-trip is unverified** — the old importer returns success if **≥ 1** parameter updated, so a mostly-garbage file reports success today; the Rust import must report exactly what it accepted and rejected. Matrix U12. (adr/0005 §Risks 2, task `DOMAIN-8`)
37. 🔴 **The config schema is weak in three specific ways**: validation is per-parameter only (so an unsteamable machine is accepted — the oracle's rule `emergency_temp > steam_setpoint + emergency_hysteresis` gives 10 °C margin at defaults, 25 °C at maxima); bools and strings are always accepted; eight string-length constants are unenforced; `String::toInt()/toDouble()` return 0 on garbage. (inventory.md §6.6, prior-implementation-findings.md §2 #8 and §10 O4)
38. 🟠 **The C++ `SENSOR_ERROR` recovery clock is measured from entry, not from the error clearing** — the guard at `BaseState.h:145-148` has no `if constexpr` exclusion for `SENSOR_ERROR`, so `checkSpecificTransitions` (and the reset) never runs while the probe is faulted. The source comment claims the opposite; this inventory initially believed the comment and was corrected. (inventory.md §5.12, prior-implementation-findings.md §3.1)
39. 🟠 **`hasUserActivity()` and `shouldExitStandby()` are hard `return false` stubs** — the water switch cannot wake the machine from standby, and this inventory had described a wake path that does not exist. (prior-implementation-findings.md §2 #14)
40. 🟠 **The C++ state-machine test coverage is far thinner than the 303-macro count suggests** — `test_state_machine` exercises only gMock plumbing, `test_pid_state_transitions` tests hand-written mock states, and two suites never include the real state sources. This directly undercuts treating "303 tests" as a safety net; the count is also unreconciled (303 macros / 340 cases / 280 / 234). (prior-implementation-findings.md §2 #16 and §14, inventory.md §2.5)
41. 🟠 **`P_ON_M`/`P_ON_E` are inverted between the firmware header and the host-test stub**, so any existing host test exercises the opposite branch — the existing suite cannot serve as the oracle until `ORACLE-1` fixes it. (inventory.md §7.2 #15, compatibility-matrix.md §4.3)
42. 🟠 **`PIN_HEATER = 2` is an ESP32 boot-strapping pin and `PIN_STEAMLED = 1` is UART0 TX**, colliding with the 115200 console; the comment says the LED "was moved" and it was not. GPIO16/17 are *not* strapping pins (retires a phantom risk). (inventory.md §1.3, §7.1 items 1–2)
43. 🟠 **The I²C bus is shared between a 10 ms priority-18 control read and priority-6 display flushes on a 100 kHz bus, with no `setClock`**; the C++ already has this contention unmanaged. The design resolves it with `try_lock` + skip-the-sample, making inversion structurally impossible. (architecture.md §5, inventory.md §3.1)
44. 🟡 **The state ids' numeric gaps are load-bearing** (`isBrewState` 31..34, `isBackflushState` 60..63, `state <= 63` for LED eligibility), and `executeTransition`'s **self-transition skip is load-bearing** — it is what makes the SENSOR_ERROR clock bug work as it does. (inventory.md §5.1, prior-implementation-findings.md §2.1)
45. 🟡 **The self-transition skip is confirmed by both audits independently** — listed here as a porting invariant that must be reproduced, not refactored away. (prior-implementation-findings.md §2.1)

**Toolchain / build landmines**

46. 🔴 **`-D warnings` on the device target cannot pass** — `esp-idf-sys` 0.38 emits ~1300 `esp_idf_*` cfgs without matching `rustc-check-cfg`, so every use is an `unexpected_cfgs` warning. The workflow specifies `-D warnings` for every target and will fail once real device code exists. (prior-implementation-findings.md §8.3, tooling.md §5)
47. 🔴 **Cargo does not forward a dependency's `cargo:rustc-link-arg` to the binary package**, so without `embuild::espidf::sysenv::output()` in the binary crate's `build.rs` the final link contains no ESP-IDF archives and fails on undefined `pthread_create`/`write`/`abort`. (prior-implementation-findings.md §8.5)
48. 🟠 **`ESP_IDF_SYS_ROOT_CRATE` must be exported for a virtual workspace**, or `esp-idf-sys` silently ignores `extra_components` — including the LittleFS component. Silent failure that looks like a broken component. (prior-implementation-findings.md §1.3, §8.4)
49. 🟠 **`--cfg espidf_time64` is mandatory** or the build silently uses 32-bit `time_t`; it is set once here (good) but the parallel branch sets it in two places cargo does not keep in sync. `IDF_TOOLS_PATH` is ignored by `esp-idf-sys` (the knob is `ESP_IDF_TOOLS_INSTALL_DIR`). (tooling.md §8, prior-implementation-findings.md §8.5)
50. 🟠 **Partition tables cannot be set from `sdkconfig.defaults`**; the knob is `[idf] partition_table` in `.cargo/config.toml` plus `--partition-table` at flash time, and **the flashable app image does not contain the table** (first byte is the `0xE9` app magic) — which is why an app-only flash can never fix a layout mismatch, the same failure `BOOT-1` catches. (prior-implementation-findings.md §8.5, tooling.md §8)
51. 🟠 **`.cargo/config.toml` is read from the cwd upward, not `--manifest-path`**, so target recipes must `cd firmware/` first or fail with the same misleading `can't find crate for core`. (tooling.md §3)
52. 🟡 **`.cargo/config.toml` key is `linker`, not `rustc-linker`** (cargo 1.97 rejects the latter), and embuild only warns when `$RUSTC_LINKER` is missing so the failure surfaces late. `espflash monitor` needs a TTY and is unusable from CI or an agent; `cargo bloat` cannot work against a stripped release profile. (prior-implementation-findings.md §8.5)
53. 🟡 **`esp-idf-hal` 0.47's `hal::onewire` is unusable** (CRC/command helpers still under `todo:`, no `attach_interrupt`) — bit-banging was used instead. `gptimer_set_alarm_action` rejects `alarm_count == reload_count`, so `reload_count: 0` is the correct periodic config. `esp-idf-svc` 0.53's `embassy-time-driver` **does not link on its own**. (prior-implementation-findings.md §1.3, compatibility-matrix.md §6)
54. 🟡 **This host intermittently drops outbound TLS** for espup/cargo/python while `curl` and `git` keep working — a single failure is not evidence of a blocker; the frontend cannot be built here (`buildfs` has never run), so **the real gzipped web-UI size is unknown** (only datapoint: a live device reported 225,280 of 393,216 bytes used). (prior-implementation-findings.md §8.5, §9.2, matrix U17)
55. 🟡 **The C++ app image is at 90.4 % of its partition** — 1,539,657 B of 1,703,936 B, 154 KiB real headroom — which is why size is gated in CI (fail above the partition, warn above 85 %). (inventory.md §2.2, adr/0004)

## 4. Verification strategy

- **The C++ firmware stays in the tree and buildable for the whole migration and is the oracle** — every behavioural claim is checked against it, not against the documentation; `just cpp-build`/`cpp-test` are CI-enforced (`architecture.md` §7, tooling.md §5 job 3, SKILL.md §1).
- **Host-test surface = `cc-domain` + `cc-hal` + `cc-drivers`**, which `cargo check` and `cargo test` without any ESP toolchain; the crate split exists so `just test` stays fast (architecture.md §6.6, tooling.md §3).
- **Table-driven state machine tests** against `docs/state-machine-architecture.md`, plus **one test per state × per pre-emptive condition** asserting the target state *and* that heater duty is 0 (architecture.md §7).
- **PID parity by golden vectors** captured from the real `PID_v1` under test and replayed against the Rust port, tolerance 1e-9, covering both modes, saturation, integrator clamping, sample-time changes and MANUAL↔AUTOMATIC transitions; "if any golden vector cannot be matched, stop and report rather than adjusting the tolerance" (`task-list.md` ORACLE-2, DOMAIN-3). Recommended upgrade from CSV goldens to a *compiled* C++ oracle (`prior-implementation-findings.md` §4).
- **`config.json` round-trip**: the real C++ export fixture (`tests/fixtures/config-export-cpp.json`, 96 leaves, credentials scrubbed) imports with every parameter accounted for, re-exports equivalently, and blob encode/decode round-trips (ORACLE-4, DOMAIN-4, DOMAIN-8, architecture.md §7).
- **Layout-guard tests over every partition-list case** — happy path, the C++ table (must fail), empty list, `ccfs` with the wrong subtype — asserting halt (BOOT-1).
- **Interlock property test over the interlock powerset**, asserting duty is 0 whenever any blocking interlock is set, plus a **compile-fail test** proving `HeaterCommand` has no other constructor (DOMAIN-2).
- **ZACwire decode tests on recorded symbol slices** including parity failures, the 221/222 sentinels and the 0–180 °C reject (DOMAIN-6, architecture.md §7).
- **Display golden-image tests** with the anchor shim verified against measured deltas (0 px `fub20`, 2 px `profont17`, 1 px `profont11/10`); SPIKE-5 separately diffs `u8g2-fonts` bitmaps against U8g2's C renderer (DOMAIN-7, SPIKE-5).
- **Driver tests against a mock `embedded-hal` bus**, explicitly including NAK and short-read paths that the C++ ignores (DRV-2, architecture.md §7).
- **Device-level verification**: NVS write → power-cycle → read-back of every parameter; control-tick jitter and PWM edge accuracy measured on hardware; deliberately stalled `control` must cause a reset (APP-1, APP-2, architecture.md §7).
- **Parity phase on device**: PARITY-1 PID duty-trace equivalence, PARITY-2 emergency debounce wall-clock equivalence (injecting over-temperature *at the sensor abstraction*, never by overheating), PARITY-3 identical state-transition traces with pump/valve disconnected, PARITY-4 every endpoint response and MQTT topic diffed.
- **CI gates**: `host` job (fmt, clippy, test, no ESP toolchain — the job that actually gates correctness), `firmware` job (matrix over targets, fails if the app image exceeds the partition, warns above 85 %), `cpp-baseline` job (tooling.md §5).
- **Negative tests by construction**: `SPIKE-8` flashes the Rust image with the **C++ partition table** and requires a halt with the pins measured inactive — the guard is proven by making it fire (task-list.md SPIKE-8).
- **Actuator safety protocol**: every task that energises anything is marked ACTUATOR with a written procedure (element physically isolated, observed at the relay input pin or via an LED, duty swept 0→100→500→1000→0, power-cut means); CUT-1, the first run that heats water and pulls a shot, requires explicit user go-ahead and is listed "so it is not forgotten, not so an agent can decide to do it" (task-list.md, SKILL.md §4).
- **Honesty rule**: record exact commands and real counts, what could not be verified and why, compile-level ≠ runtime; if hardware is unavailable or a gate cannot be run, record that and do not claim the gate passed (SKILL.md §5).

## 5. Migration sequencing

- **Phase 0 (done)**: inventory, platform comparison, SPIKE-1 size spike, architecture/crate split, tooling, ADRs 0004/0005. Exit gate = all `just` recipes green on the host, C++ builds, no device flash. (task-list.md Phase 0)
- **P0 prerequisite collapses to one courtesy question**: may the attached board be erased? Until answered, prefer `HW: no` tasks; Phase 1 is designed to complete entirely without hardware. (task-list.md P0, P0.1)
- **Phase 1 — pure logic, `HW: no`**: `ORACLE-1` (fix the C++ stub's inverted `P_ON_M`/`P_ON_E` *first*, so the existing suite can serve as oracle) → `ORACLE-2`/`ORACLE-4` (capture vectors and the real `config.json` fixture) → `DOMAIN-1` → `DOMAIN-2` → `DOMAIN-3`/`DOMAIN-4` → `DOMAIN-8`, `SAFETY-1`, `BOOT-1`, `DOMAIN-5`/`DOMAIN-6`/`DOMAIN-7`.
- **Phase 2 — feasibility spikes, mostly `HW: esp32`, research only**: `SPIKE-2` (first flash, relay board disconnected, measure pins) → `SPIKE-8` (layout guard + config migration on device) → `SPIKE-4` (re-scoped away from TSIC) → `SPIKE-5` (font parity), `SPIKE-6` (SSE socket limits), `SPIKE-7` (provisioning, with the `esp-wifi-provisioning` feature check as step 0). They run early precisely because they are the tasks that can invalidate the design.
- **Phase 3 — board and drivers** (`BOARD-1` → `BOARD-2` → `BOARD-3`, `DRV-1..4`); Phase 4 — application (`APP-1` wiring → `APP-2` store → `NET-1..5`, `UI-1`); Phase 5 — parity `PARITY-1..4`, then `CUT-1` (user-gated), `CUT-0` (migration doc), `CUT-2` (release).
- **Every spike carries a recorded verdict, and a failed spike updates the matrix and the task list *before* Phase 3 starts** — the plan treats its own documents as the control surface, and the skill mandates "update the documents first, then continue" (task-list.md Phase 2 gate, SKILL.md §8).
- **Phase gates are all-or-nothing and honest**: if hardware is unavailable or unsafe, record it and do not claim the gate passed.
- **Riskiest ordering identified — placing hardware after all the domain logic is good; placing the *board relay-polarity* decision after BOARD-1 is not.** `BOARD-2` is blocked on a question only a meter on the coil with the boiler disconnected can answer, and it gates BOARD-3 (the heater PWM), which gates APP-1 and therefore the whole application layer. Everything from BOARD-2 onward is serialised behind one unresolved hardware fact. (task-list.md BOARD-2/BOARD-3, matrix U14)
- **Second-riskiest ordering**: `ORACLE-1` must precede every PID task; while the stub's `P_ON_M`/`P_ON_E` are inverted, any PID golden vector would certify the wrong branch. `BOOT-1` must precede every on-device task, because a half-migrated device is the failure the guard exists to catch. (task-list.md ORACLE-1, BOOT-1 "Blocks: any on-device task")
- **Third**: Phase 1's exit gate text still demands NVS key vectors that ADR 0005 deleted — a stale gate that would either fail spuriously or, worse, be quietly reinterpreted as "read the old NVS", which the skill §6a explicitly forbids.
- **The recommended alternative base is not this branch**: `prior-implementation-findings.md` §6 recommends adopting the parallel `rewrite/rust` branch as the implementation base and carrying across only `BOOT-1`, ADR 0005 itself, the mise/rustup documentation, the broader build/CI/security findings, and the RMT-vs-poller question — i.e. this branch's sequencing is proposed for a from-scratch implementation that the same document argues against.
